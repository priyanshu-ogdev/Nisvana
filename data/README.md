# Project AEGIS — Data Layer Architecture & File Hierarchy

> **Location:** `data/`  
> **Storage Specification:** High-throughput NVMe storage recommended (TB-scale acoustic data pipeline)

---

## 1. Overview

The `data/` directory is the physical data layer for Project AEGIS. It organizes audio through an auditable progression of stages: from raw downloads to DSP preprocessed audio, split manifests, mixture generation, WebDataset sharded training artifacts, and exported deployment models.

```
data/
├── raw/                 # Stage 1: Unaltered downloads from 10 real acoustic sources
├── processed/           # Stage 2: Preprocessed audio (48 kHz, -23 LUFS, VAD trimmed, clean mono)
├── splits/              # Stage 3: Split manifests (train, val, test_generalization isolation)
├── augmented/           # Stage 4: Policy-isolated augmentations (empty under real-recordings-only policy)
├── forge/               # Stage 5: Multi-branch synthetic mixtures (SE, Classifier, AEC)
├── shards/              # Stage 6: WebDataset sharded tar files for high-throughput DataLoader streaming
├── manifests/           # Stage 7: Verified bibliography & audit checksum manifests
├── onnx_models/         # Stage 8: Exported and quantized ONNX models for edge deployment
└── eval_reports/        # Stage 9: SIH compliance evaluation reports and per-class metrics
```

## 2. Directory Hierarchy & Specifications

### 2.1 `data/raw/` — Raw Dataset Archives
Contains unaltered raw downloads fetched by [data_forge](file:///d:/Nisvana/data_forge/README.md#31-fetcher-submodule-data_forgefetcher). Each subfolder represents an authenticated research corpus:

| Folder | Source Dataset | Size / Content | Format |
|---|---|---|---|
| `raw/noisex92/` | NOISEX-92 (NATO RSG.10) | Tank (Leopard), Howitzer (M109), Jet (F-16), Destroyer | 19.98 kHz / 16 kHz WAV |
| `raw/shared_explosions/` | SHAReD (Takazawa et al.) | Controlled high-explosive blasts (C-4, TNT, ANFO) | 48 kHz 24-bit WAV |
| `raw/drone_audioset/` | DroneAudioSet (Al-Emadi et al.) | Multi-rotor UAV ego-noise and flybys | Parquet / WAV |
| `raw/mad/` | Military Audio Dataset (MAD) | Heavy machinery, tracked vehicles, firearms | 48 kHz WAV (Kaggle) |
| `raw/gunshot_dryad/` | Ballistic Gunshots (Dryad) | Supersonic shockwave & muzzle blast recordings | High-bandwidth WAV |
| `raw/sirens_urban/` | ESC-50 & UrbanSound8K | Ambulance, fire, police sirens, wind | 44.1 kHz WAV |
| `raw/openslr_rirs/` | OpenSLR-28 (Ko et al.) | Real measured room impulse responses (RWCP, AIR) | 48 kHz WAV |
| `raw/vctk_demand/` | VCTK + DEMAND (Diverse Env) | Clean speech targets & stationary acoustic noise | 48 kHz WAV |
| `raw/dns_challenge/` | INTERSPEECH DNS Challenge | Fullband clean speech and non-stationary noise | 48 kHz WAV |
| `raw/aec_challenge/` | ICASSP AEC Challenge | Acoustic echo cancellation matched quadruplets | 48 kHz WAV |

### 2.2 `data/processed/` — Standardized Audio
Output of the 10-step preprocessing pipeline ([data_forge Preprocessor](file:///d:/Nisvana/data_forge/README.md#32-preprocessor-submodule-data_forgepreprocessor)). Standardized to:
- **Sample Rate**: 48,000 Hz fullband (polyphase resampled from native rates).
- **Loudness**: $-23.0 \pm 0.5$ LUFS (integrated loudness per ITU-R BS.1770-4).
- **Peak Limit**: $-1.0$ dBFS true peak limiter ceiling.
- **Channels**: Mono downmixed with equal-power scaling ($\frac{L+R}{\sqrt{2}}$).
- **Format**: Standard PCM 16-bit WAV.
- **Subdirectories**: Partitioned by `UnifiedClass` (e.g., `processed/tank_tracked/`, `processed/clean_speech/`, `processed/explosion_blast/`).

### 2.3 `data/splits/` — Origin-Aware Split Manifests
Ensures absolute speaker and recording-session isolation across pipeline splits:
- `train_manifest.json`: ~80% of data for training models.
- `val_manifest.json`: ~10% for checkpoint selection and worst-class monitoring.
- `test_generalization_manifest.json`: ~10% strictly reserved for unseen generalization testing. Datasets tagged `is_generalization_only=True` are never mixed into training.

### 2.4 `data/forge/` — Flat-File Branch Mixtures
Generated by [data_forge Mixer](file:///d:/Nisvana/data_forge/README.md#34-mixer-submodule-data_forgemixer) across three distinct model branches:
- **`forge/branch_speech_enhancement/`** (Models 1–3):
  - `noisy/`: Mixed audio ($x = s * h + n$) at dynamic SNRs ($-5.0$ to $+20.0$ dB).
  - `clean/`: Reverberant speech ground truth target ($s * h$).
  - `rir/`: Measured room impulse response convolution filters ($h$).
  - `*.json`: Sidecar metadata with SNR, SyncTier, RMS, and source dataset attribution.
- **`forge/branch_classifier/`** (Model 4):
  - `audio/`: 200ms audio slices labeled into 3-way classifier categories (`stationary_harmonic`, `non_stationary_transient`, `speech_dominant`).
  - `labels.json`: Index of all slices with harmonicity indices and class labels.
- **`forge/branch_aec/`** (Model 5):
  - Matched quadruplets (`mic/`, `farend/`, `nearend/`, `echo/`) with near-end speech and acoustic echo.

### 2.5 `data/shards/` — WebDataset Tar Shards
Packed sequential-read archives created by [data_forge Exporter](file:///d:/Nisvana/data_forge/README.md#35-exporter-submodule-data_forgeexporter). Sharded at 2,048 samples per `.tar` archive for high-throughput streaming into PyTorch `DataLoader` instances without filesystem inode bottlenecks:
- `shards/speech_enhancement/se_shard_000000.tar`, etc.
- `shards/classifier/clf_shard_000000.tar`, etc.
- `shards/aec/aec_shard_000000.tar`, etc.
- `shards/DATASET_CARD.md`: Machine-readable card documenting sample counts, SNR distributions, and licensing compliance.

### 2.6 `data/onnx_models/` — Deployment Models
Houses exported ONNX and quantized INT8 models produced by [inference Engines](file:///d:/Nisvana/inference/README.md#21-inference-engines--optimization-inferenceengines):
- `se_primary.onnx` / `se_primary_quantized.onnx`: DeepFilterNet3 Base.
- `se_escalation.onnx`: DeepFilterNet3 Escalation (20ms lookahead).
- `se_crosscheck.onnx`: CleanUMamba SSM backend.
- `clf_gate.onnx`: Conformer gating classifier.
- `aec_gate.onnx`: Gated AEC neural post-filter.

## 3. Storage & I/O Optimization on DGX Spark

To maximize I/O throughput on the DGX Spark's 128 Grace cores:
1. Place `data/` on an NVMe-backed mount (set `DATA_FORGE_DATA_DIR=/nvme/aegis/data` in `.env`).
2. WebDataset shards stream sequentially via POSIX read-ahead buffers, completely avoiding random disk seek overhead.
3. The disk space monitor requires at least 50 GB free disk safety margin before commencing downloads or mixing.
