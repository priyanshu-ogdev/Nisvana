# Project AEGIS — Machine Learning Training Pipeline & Model Engine

Project AEGIS (`training/`) is an autonomous, scientifically grounded deep learning engine designed to train, fine-tune, evaluate, and export acoustic noise reduction, speech enhancement (SE), and acoustic gating models. The pipeline is calibrated for **fullband 48,000 Hz** audio, specifically targeting the extreme acoustic stresses of defence environments: tracked combat vehicles, jet cockpits, artillery shockwaves, naval operations rooms, multi-rotor drone ego-noise, and high-velocity turbulent wind.

---

## 1. Pipeline Overview & Step-by-Step Walkthrough

The training engine ingests pre-split WebDataset sequential `.tar` archives generated by the AEGIS Data-Forge and executes a 9-stage lifecycle:

```
[WebDataset Shards: se-train-*.tar]
                │
                ▼
  [1. Weighted Shard Sampler] ───────────► Sync-tier down-weighting (0.25x for 16k upsampled)
                │                         Class oversampling (6x tank, 5x howitzer, 4x jet)
                ▼
  [2. Pre-Batch Augmentation] ──────────► SpecMix dynamic time-frequency masking on mixture
                │                         (Clean speech target remains 100% untouched)
                ▼
  [3. Architecture Forward Pass] ────────► Models 1-5 via unified factory (build_model_for_key)
                │
                ▼
  [4. Joint Loss Computation] ──────────► Multi-res STFT + Local SNR + SI-SNR + STFT Consistency
                │                         (Vendored DeepFilterNet3 loss with standalone fallback)
                ▼
  [5. Optimizer & Backprop] ────────────► AdamW, learning rate warmup, gradient clipping
                │
                ▼
  [6. EMA Shadow Weight Update] ────────► Exponential Moving Average update (decay=0.999)
                │
                ▼
  [7. Evaluation Cadence] ──────────────► Per-sample metrics breakdown by unified_class
                │                         (pesq_aggregate, pesq_<class>, snr_<class>)
                ▼
  [8. Worst-Class Checkpoint Guard] ────► Rejects checkpoints if fragile classes regress
                │                         (Unconditional class high-water mark banking)
                ▼
  [9. Checkpoint Pruning Engine] ──────► Retains best + last N checkpoints, prunes stale states
```

| :--- | :--- | :--- | :--- | :--- |

| **`aegis-se-escalation`** (Model 2) | High-difficulty / negative SNR escalation | DeepFilterNet3 (high-capacity semi-causal configuration) | **40 ms lookahead** (`df_lookahead=2`, `conv_lookahead=2`) | Multi-Resolution STFT + Framewise Local SNR |

| **`aegis-clf-gate`** (Model 4) | Real-time acoustic environment & gate classifier | 1D CNN + Adaptive Pooling (MobileNetV3-Audio class) | Sub-segment fast classification | Weighted Cross-Entropy over 3 collapsed classes (`harmonic`, `impulsive`, `speech_dominant`) |
| **`aegis-aec-gate`** (Model 5) | Dual-channel acoustic echo cancellation | DeepVQE Gated Filterbank | Low latency streaming | Near-end MSE / ERLE penalty |

## 4. Deep Dive into Integrated Features & Scientific Rationale

### 4.1 Dual-Metric Worst-Class Checkpoint Guard
**Location**: [`training/callbacks/worst_class_checkpoint_selector.py`](file:///d:/Nisvana/training/callbacks/worst_class_checkpoint_selector.py)

- **The Problem**: Standard training frameworks accept a new checkpoint whenever the aggregate validation metric improves. In defence datasets, thin fragile classes (`rotor_vehicle_drone`, `wind`) represent a small percentage of total validation samples. A checkpoint can improve aggregate PESQ from 2.50 to 2.70 while catastrophic regression occurs on drone noise (e.g. dropping from 2.40 to 2.10).
- **Dual-Metric Watching**: Monitors both `pesq_<class>` (MOS scale) and `snr_<class>` (dB scale) with independent tolerances:
  - `max_allowed_regression_pesq: float = 0.05`
  - `max_allowed_regression_snr_db: float = 1.0`
- **Unconditional High-Water Mark Banking**: Class-level bests are updated unconditionally on every evaluation step (`max(prior, current)`). If a fragile class improves on a step where the aggregate metric remained flat, that improvement is immediately banked. Subsequent regressions from that peak are prevented from slipping through.

### 4.2 Multi-Resolution Spectral & Joint Loss Stack
**Location**: [`training/losses/multires_loss.py`](file:///d:/Nisvana/training/losses/multires_loss.py)

The speech enhancement loss combines four complementary objectives:
$$\mathcal{L}_{\text{total}} = 500 \cdot \mathcal{L}_{\text{mag}}^{(\gamma=0.3)} + 500 \cdot \mathcal{L}_{\text{cplx}} + 10^{-3} \cdot \mathcal{L}_{\text{local\_snr}} + \alpha \mathcal{L}_{\text{si\_snr}} + \beta \mathcal{L}_{\text{stft\_cons}}$$

1. **Power-Law Compressed STFT Loss** ($\mathcal{L}_{\text{mag}}, \mathcal{L}_{\text{cplx}}$): Computes L1 distance over multi-resolution spectrograms ($N_{\text{fft}} \in [256, 512, 1024, 2048]$). Compresses magnitude ($\gamma = 0.3$) to mirror human perceptual loudness, preserving complex phase.
2. **Framewise Local SNR Loss** ($\mathcal{L}_{\text{local\_snr}}$): Evaluates segmental SNR over 480-sample frames (10ms) with 240-sample hop. Prevents loud, clean segments from masking localized quiet distortion moments.
3. **Scale-Invariant SNR Loss** ($\mathcal{L}_{\text{si\_snr}}$): Energy-projected, zero-mean signal alignment invariant to global volume scale differences.
4. **STFT Consistency Loss** ($\mathcal{L}_{\text{stft\_cons}}$): Penalizes discrepancies between complex STFT frames and time-domain signals ($|\text{STFT}(\text{iSTFT}(X)) - X|$).
- **Dual Routing**: Automatically utilizes native `df.loss.Loss` if `deepfilternet[train]` is installed; falls back to pure PyTorch/NumPy with identical formulation if uninstalled.

### 4.3 Exponential Moving Average (EMA)
**Location**: [`training/callbacks/ema.py`](file:///d:/Nisvana/training/callbacks/ema.py)

- Maintains shadow weights updated on each training step:
  $$\theta_{\text{EMA}} \leftarrow \beta \theta_{\text{EMA}} + (1 - \beta) \theta_{\text{model}}$$
- **Decay Parameter**: $\beta = 0.999$ calibrated for tens of fine-tuning epochs.
- **Scientific Literature Calibration**: Grounded in Kaizen (*arXiv:2106.07759*) and deep learning optimization (*arXiv:2411.18704*), with explicit notes from speech enhancement diffusion studies (*arXiv:2505.05216*) recommending an on/off ablation toggle against raw iterates.

### 4.4 SpecMix Dynamic Data Augmentation
**Location**: [`training/data/spec_augment.py`](file:///d:/Nisvana/training/data/spec_augment.py)

- Replaces rectangular time-frequency spectrogram regions with random spectral noise slices rather than zeroing bins.
- **Physical Rationale**: Zeroing bins creates unnatural silence voids that confuse deep filtering networks and speech detectors. SpecMix maintains the energy floor while forcing the model to reconstruct speech through continuous masking.
- **Target Invariant**: Applied strictly to noisy mixture spectrograms; target clean speech spectrograms are never masked.

### 4.5 SNR Curriculum Scheduling
**Location**: [`training/schedulers/snr_curriculum.py`](file:///d:/Nisvana/training/schedulers/snr_curriculum.py)

- Controls the mean of the SNR sampling distribution during synthetic mixture batch generation across epochs.
- Configurable direction:
  - `"easy_to_hard"`: Starts at higher SNR (+15 dB) and decays exponentially toward low/negative SNR (-5 dB) based on SDCL (*arXiv:2510.18533*).
  - `"hard_to_easy"`: Starts at low SNR and expands toward cleaner mixtures based on ASR noise curriculum studies (*arXiv:2101.10382*).

### 4.6 Weighted Shard Sampler & Sync-Tier Down-Weighting
**Location**: [`training/data/weighted_shard_sampler.py`](file:///d:/Nisvana/training/data/weighted_shard_sampler.py)

- **Sync-Tier Penalization**: High-fidelity 48kHz native recordings (Tier 1) receive $1.00\times$ weight. 16kHz upsampled legacy audio (Tier 3) is down-weighted to $0.25\times$ to avoid biasing filterbanks toward missing high frequencies.
- **Class Oversampling**: Thin defence platforms receive explicit multipliers:
  - `tank_tracked`: $6.0\times$
  - `artillery_howitzer`: $5.0\times$
  - `jet_cockpit`: $4.0\times$
  - `rotor_vehicle_drone`: $5.0\times$
  - `wind`: $5.0\times$
- **Split Preservation**: Resolves strictly to `se-train-*.tar`, `se-val-*.tar`, or `se-gentest-*.tar`. Generalization test datasets (WHAM, MUSAN, LibriSpeech) are isolated and never leak into training.

## 5. Execution & Operational Runbook

All training commands can be launched directly via Python modules or via the unified automation scripts in `scripts/`:

### Training Individual Models

```bash
# Model 1: Primary Real-Time SE (0ms lookahead streaming)
python -m training.scripts.train_se_primary [--resume PATH]
# Or using script:
bash scripts/07_train_se_primary.sh
# PowerShell: .\scripts\07_train_se_primary.ps1

# Model 2: Escalation SE (40ms lookahead semi-causal)
python -m training.scripts.train_se_escalation [--resume PATH]
# Or using script:
bash scripts/08_train_se_escalation.sh
# PowerShell: .\scripts\08_train_se_escalation.ps1

# Model 3: CleanUMamba Cross-Check
python -m training.scripts.train_se_crosscheck [--resume PATH]
# Or using script:
bash scripts/09_train_se_crosscheck.sh
# PowerShell: .\scripts\09_train_se_crosscheck.ps1

# Model 4: Acoustic Environment & Escalation Classifier
python -m training.scripts.train_classifier [--resume PATH]
# Or using script:
bash scripts/10_train_classifier.sh
# PowerShell: .\scripts\10_train_classifier.ps1

# Model 5: Acoustic Echo Cancellation (--force required)
python -m training.scripts.train_aec --force
# Or using script:
bash scripts/11_train_aec.sh --force
# PowerShell: .\scripts\11_train_aec.ps1 -force
```

### Master Sequential Pipeline
To train all primary models (Model 1, Model 2, Model 3, Model 4) in automated succession:

```bash
# Linux
bash scripts/12_train_all_models.sh

# Windows (PowerShell)
.\scripts\12_train_all_models.ps1
```
